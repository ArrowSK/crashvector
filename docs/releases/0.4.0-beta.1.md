# CrashVector 0.4.0-beta.1

M12 corrects the whole-vehicle physics architecture after the M11 production path was observed to produce visibly implausible rebound and vertical motion. The corrective release stops using the deformable point-mass graph as the authoritative world-motion model for supported desktop scenarios.

## What changed

- Passenger cars and heavy articulated trucks use Godot `RigidBody3D` for whole-vehicle mass, inertia, translation, rotation, gravity and collision response.
- Continuous collision detection is enabled for the production rigid chassis.
- Passenger-car road support uses four force-producing raycast suspension contacts; the articulated truck uses six suspension contacts.
- The old visual wheel-floor clamp and rigid wheel-sphere road-contact paths are not the production support model.
- Rigid wall, concrete barrier, pole and tree now include real `StaticBody3D` collision geometry.
- The M11 44-node passenger-car structure remains as a local deformable front structure anchored to the protected rigid chassis instead of moving the entire vehicle through custom point-mass integration.
- The rigid passenger-car collision volume stops at the protected cell/subframe. A forward collision-distance probe measures available crush travel ahead of it.
- Progressive crash-box/front-rail resistance is applied to the real rigid chassis while the same measured travel drives visible/local nose shortening.
- Heavy-truck rear underride geometry is a real collision face, preventing the passenger-car structure from climbing an exposed low frame rail and generating an artificial jump.
- Production metrics and replay use the rigid chassis velocity/momentum state for supported M12 scenarios.
- M12 explicitly refuses to run unported target types through the old world-motion solver. Rigid lorry, motorcycle, bicycle and pedestrian production simulation are temporarily unavailable in this corrective beta.
- Visual Compare and Comparison Lab are temporarily unavailable because their synchronous historical runner still uses the reduced-order world solver. CrashVector does not silently mix the old solver into M12 production results.

## Regression results on the release branch

The dedicated engine-physics gate runs actual Godot physics frames.

For the 50 km/h generic B-class centred rigid-wall regression, the accepted branch recorded approximately:

- 0.541 m front crush;
- 0.731 m/s maximum reverse speed;
- 0.136 m maximum retreat after first contact;
- 0.002 m maximum vertical rise;
- 0.041 m/s maximum vertical speed;
- 0.32 degrees maximum pitch.

For the 90 km/h generic B-class versus 18-tonne articulated-truck regression after the physical underride guard was added, the accepted branch recorded approximately:

- 0.948 m passenger-car front crush;
- 0.981 m/s maximum passenger-car reverse speed;
- 0.002 m passenger-car vertical rise;
- 0.117 m/s passenger-car maximum vertical speed;
- 0.33 degrees passenger-car pitch;
- effectively zero truck vertical rise in the measured regression window.

These numbers are project regression measurements for generic educational models, not manufacturer or regulatory crash-test results.

## Scope and validation

M12 improves visible mechanical plausibility by assigning whole-body dynamics to the engine physics solver and restricting the custom structural model to the deformation problem it is intended to approximate. It does not turn CrashVector into a finite-element crash package or validate a generic class against a production vehicle.

The historical M8 NHTSA-linked correlation runner remains a separate reduced-order regression reference. Its existence does not validate the M12 rigid-body/crush coupling.

See `docs/M12_HYBRID_PHYSICS.md` for the architecture and explicit coverage boundaries.

Signing limitations remain unchanged unless signing credentials are configured in CI: macOS uses the existing ad-hoc/unnotarized fallback and Windows may be unsigned.
