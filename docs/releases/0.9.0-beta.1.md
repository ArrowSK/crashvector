# CrashVector 0.9.0-beta.1

`0.9.0-beta.1` is the next feature beta after the verified `0.8.0-beta.3` M17/M18 line. It brings the source forward through M22 and includes the presentation corrections developed after the first Kenney integration.

This is still an educational simulation release. The new M19–M22 models are generic project models and must not be described as certified reconstruction, manufacturer crashworthiness, biomechanics, injury prediction or regulatory validation.

## Passenger-car presentation correction

The Kenney Car Kit integration now preserves each source vehicle's neutral silhouette instead of globally stretching the pristine mesh onto the structural cage at load time. CrashVector captures a neutral structural presentation state and applies only the live-minus-neutral structural displacement to the uniformly scaled source body.

The six generic passenger classes use six distinct pinned Car Kit bodies:

- A — `hatchback-sports.glb`
- B — `sedan-sports.glb`
- C — `sedan.glb`
- D — `taxi.glb` as the closest additional sedan-shaped visual proxy in the pinned pack
- J — `suv.glb`
- M — `van.glb`

Wheel presentation is aligned to the selected Kenney body's wheel centres without changing authoritative suspension/contact geometry. The presentation pass also refines materials, lighting, road presentation, selection marking and setup/impact/aftermath camera composition while preserving the existing desktop workflow.

## M19 — contact fidelity and validation foundation

M19 adds observation and diagnostics without replacing Godot collision response:

- non-ground Godot contact-manifold diagnostics including reported point count, centroid/normal, local spread and reported impulse;
- explicit diagnostic-only scope with no solver feedback;
- three passenger-car front-crush observation rays (centre plus two lateral rays) to reduce offset/oblique blind spots;
- replay/analysis propagation of the contact diagnostics;
- public NHTSA/IIHS protocol-geometry references retained separately from outcome-correlation claims;
- manual aligned/offset/oblique/broadside observation matrix for evidence review.

Reported contact spread is not a physical contact-patch area and does not create an external validation corridor.

## M20 — heavy and other-vehicle deformation

The generic heavy truck, rigid lorry and riderless motorcycle retain Godot rigid-body world motion and gain bounded target-specific local deformation:

- heavy truck: front/rear/side deformation;
- rigid lorry / box truck: front/rear/side deformation with collision-face retreat;
- riderless motorcycle: bounded frame/fork front/rear/side deformation;
- oblique contacts may contribute both longitudinal and lateral demand.

The old riderless-bicycle broadside restriction remains in place.

## M21 — articulated heavy truck

The heavy articulated truck is no longer represented by one tractor/trailer rigid assembly. M21 uses:

- one trailer `RigidBody3D`;
- one tractor `RigidBody3D`;
- a constrained `Generic6DOFJoint3D` fifth wheel;
- preserved combined scenario mass through a generic tractor/trailer mass split;
- separate tractor/trailer contact diagnostics and presentation transforms;
- replayable articulation yaw and fifth-wheel separation;
- inherited bounded M20 deformation on the body that owns the contacted structure.

Fifth-wheel limits, mass split, suspension split and deformation parameters are generic educational assumptions rather than a specific truck specification.

## M22 — cyclist and moving pedestrian

M22 adds a separate `Cyclist (generic rider + bicycle)` target while preserving the existing riderless bicycle target.

The cyclist combines the existing bicycle frame/wheels with an 11-body generic articulated rider. Five temporary rider-to-bicycle coupling joints at the seat, hands and feet release after the first production-compatible impact so rider and bicycle can follow independent post-impact trajectories. Replay records the articulated part state and rider-release state.

Pedestrians can now have 0–20 km/h initial translational speed along their selected heading. This is only initial body translation: there is no gait, propulsion, foot-placement or balance controller.

Cyclist/pedestrian output remains contact/trajectory visualisation only. There is no injury metric, tissue model, rider-control model, validated ejection model or biomechanical interpretation.

## Release engineering

Normal pushes no longer build macOS and Windows packages. The current workflow separates:

- consolidated M0–M22 Linux/Godot CI;
- manual presentation/contact-fidelity visual review;
- manual macOS Universal 2 and Windows x64 packaging/release.

The package workflow supports `none`, `smoke` and `full` validation. `none` is diagnostic-package-only and cannot publish a release. Publishing requires successful `smoke` or `full` validation plus both native packages and matching versioned release notes.

## Validation requirement

M19–M22 were initially implemented while GitHub-hosted Actions capacity was exhausted, so their development commits used `[skip ci]`. This version bump and release note do not by themselves make those changes validated.

`v0.9.0-beta.1` should be published only after the current release workflow successfully runs at least the publishable `smoke` set (preferably `full`), both native package checks pass, and the manual visual/contact-fidelity review is inspected.

## Desktop packages

When published, the canonical release pipeline will produce:

- `CrashVector-0.9.0-beta.1-macOS-universal.dmg` plus SHA-256 sidecar;
- `CrashVector-0.9.0-beta.1-Windows-x64-Setup.exe` plus SHA-256 sidecar;
- `update-manifest.json` containing the exact package filenames, sizes and hashes.

Existing prerelease installations such as `0.8.0-beta.3` are eligible to discover `0.9.0-beta.1` once the new prerelease is actually published.
