# CrashVector 0.7.0-beta.2

This corrective beta finishes the M16 presentation pass after review of the packaged `0.7.0-beta.1` desktop build. It does not change the M12–M15 collision, deformation or articulated-road-user physics model.

## UI and workflow corrections

- Automatically generated scenario names now follow the selected passenger-car class and target instead of retaining stale labels such as `B-Class vs Rigid Wall`.
- User-authored custom scenario names remain untouched when vehicle or target selections change.
- The active Scenario/Compare workspace is styled as selected rather than looking disabled.
- The broken More-menu ellipsis glyph is removed.
- Duplicate scenario/results helper text is removed and the left/right panel chrome is tightened so the 3D viewport receives more visual priority.
- The persistent status surface is simplified to Ready / Simulating / Paused / Complete.
- The editor selection ring is reduced while editing and hidden during simulation, comparison and completed replay/aftermath presentation.

## Camera composition

The previous setup framing imposed an 18 m minimum camera offset, which made ordinary crashes unnecessarily small on screen. M16.1 replaces that rule with bounds-aware framing based on the current primary-vehicle and target positions.

- setup views frame the current scenario more tightly;
- completed runs automatically reframe around the actual final crash positions;
- side and three-quarter views share the same bounded composition logic;
- the exact D-segment midsize / concrete barrier / 200 km/h packaged scenario is covered by a dedicated production regression, including final camera aim and bounds.

## Passenger-car presentation

The class-specific generated passenger-car skin remains driven by the existing deforming structural model, but the generic archetypes are strengthened so the classes read more clearly at normal editor distance.

- D-segment midsize: lower/longer stance, stronger bonnet/deck relationship and reduced hatchback-like roof profile;
- J-segment SUV/crossover: higher floor and beltline, taller bonnet/roof package and more visually distinct wheel package;
- M-segment MPV/minivan: more pronounced cab-forward layout, longer high greenhouse and more upright overall volume;
- A/C classes retain their compact/low distinctions while the B-segment remains the neutral hatchback baseline.

These are generic visual archetypes. The M16.1 visual layer does not change rigid collision geometry, mass, stiffness, structural beams, staged crush behaviour, contact probes, solver settings or the finalized M15 articulated road-user path.

## Presentation environment

The packaged scene uses a darker, more neutral engineering-visualisation sky/ground treatment so the vehicles and crash result remain the focus instead of the pale beta.1 environment.

## Validation

Release acceptance requires:

- architecture audit and project import/parse;
- existing M10 responsive-layout regression;
- M11 crush-dynamics validation;
- M12 rigid-body production validation;
- M13 progressive whole-body failure validation;
- M14 road-user/yielding-target validation;
- M15 articulated pedestrian/bicycle validation;
- M16 UX/vehicle-visual and M15 integration validation;
- M16.1 title, layout, camera, selection-marker and visual-archetype regression;
- dedicated D-segment midsize / concrete barrier / 200 km/h packaged production regression;
- Core CI and macOS Universal 2 / Windows x64 package gates.

## Modelling and evidence scope

CrashVector remains an educational physics visualisation tool. `0.7.0-beta.2` does not add manufacturer-specific crash prediction, certified accident reconstruction, homologation, biomechanics, medical/injury prediction or safety-rating capability.

Rigid lorry and motorcycle production simulation remain blocked pending their rigid-body ports. Visual Compare and Comparison Lab remain unavailable until their historical synchronous runner is replaced by a scene-based rigid-body recorder. Historical M8 calibration does not validate the M12–M16.1 production path.

## Desktop packages

The release pipeline builds and verifies:

- `CrashVector-0.7.0-beta.2-macOS-universal.dmg` plus SHA-256 sidecar;
- `CrashVector-0.7.0-beta.2-Windows-x64-Setup.exe` plus SHA-256 sidecar;
- `update-manifest.json` containing the exact package filenames, sizes and hashes.

The macOS package is Universal 2. Developer ID/notarization and Windows Authenticode are used only when the corresponding credentials are configured; otherwise normal unknown-developer/publisher warnings may still appear.
